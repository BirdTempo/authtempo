**For:** a developer who wants an MCP server whose callers sign in with authtempo.

**What it does:** `authtempo init` writes a Worker on D1 with one MCP tool, `whoami`. An MCP client signs a person in, gets an access token, and calls the tool.

## Before you start

- Node 22.18 or newer, and pnpm 12.8.1.
- A clone of the authtempo repo. The `@authtempo` packages are not on a registry yet, so your app lives in the pnpm workspace of the repo. [Choose your stack](/docs/start/) tells why.
- The CLI, built in the repo. [Run it from this repo](/docs/reference/cli/#run-it-from-this-repo) tells how.
- A Cloudflare account, for the deploy and the MCP client at the end.
- A domain on Cloudflare, for the route of the Worker. [Workers on D1](/docs/start/workers-d1/) has the deploy steps.

## Steps

1. In the folder `examples` of the clone, write the app into the folder `my-mcp`.

```sh
authtempo init my-mcp --stack mcp-server
```

2. In `examples/my-mcp`, run the next steps that the command prints, up to `pnpm dev`. They install the packages, copy `.dev.vars.example` to `.dev.vars`, and migrate the local D1 database.
3. Write a secret of 32 characters or more into `AUTH_SECRET` of `.dev.vars`. Make it with `openssl rand -base64 32`. Then run `pnpm dev`.
4. Read `src/auth.ts`. It turns on the OAuth provider with one resource, the scope `mcp:tools`, no dynamic registration, and the guarded fetch.

<Code code={auth} lang="ts" title="examples/my-mcp/src/auth.ts" />

5. Read `src/index.ts`. It mounts the metadata documents, the auth routes, and the MCP route. `requireMcpAuth` lets a request reach the tool only with a token for `/mcp` that holds `mcp:tools`.

<Code code={worker} lang="ts" title="examples/my-mcp/src/index.ts" />

6. Read `src/mcp.ts`. It is the one file that imports the MCP SDK. The tool `whoami` answers the token subject, the client id, and the scopes of the caller. The token subject is the user id for a public client, and the pairwise subject for a pairwise client.

<Code code={mcp} lang="ts" title="examples/my-mcp/src/mcp.ts" />

7. Run the test. It plays the MCP client on a local D1 database.

```sh
pnpm turbo run test --filter=my-app
```

The test signs a person in by magic link. Then it sends the authorize request with the URL of a client metadata document and PKCE, allows the consent, and exchanges the code. Last, it calls `whoami` with the access token.

8. In `wrangler.jsonc`, add a route or a custom domain for your origin, and set `BASE_URL` to that origin. The `workers.dev` address is off, so the Worker has no other address.
9. Deploy the Worker as in steps 7 to 13 of [Workers on D1](/docs/start/workers-d1/).
10. In your MCP client, add the server URL, such as `https://app.example.com/mcp`. The app has no dynamic registration, so the client must have a client metadata document.
11. Let the client connect. The first request gets 401, with the URL of the resource metadata in `WWW-Authenticate`.
12. Sign in by magic link on the page that the client opens, and allow the client on the consent page.
13. Ask the client to call the tool `whoami`.

The test passes. After step 13 the tool answers the token subject, the URL of the client metadata document as the client id, and `mcp:tools`. The client of this guide is public, so the token subject is your user id.
