**For:** an operator who answers a person that cannot pass the second factor.

**What it does:** this guide checks who the person is, then turns their factor off in process. The person then turns a new method on.

## Before you start

- A way to run code in the API's process, for the [in-process API](/docs/reference/api/#the-in-process-api).
- A written process of identity proofing, at the level that the person passed when they turned the factor on. [The threat model](/docs/concepts/threat-model/) tells why the level matters.

## Steps

1. Ask the person to try each method of the challenge first. A backup code passes when the authenticator is lost.
2. Ask the person to reset the password if they lost it. A reset does not turn the factor off.
3. Check who the person is with your identity proofing process. ASVS 5.0 6.4.4 asks for the level of the enrollment.
4. Record the check: the user id, the time, the operator, and the evidence.
5. Call the function below with the person's address. It turns every method of the user off.

<Code code={recover} lang="ts" title="The recovery of one user" />

6. Read the answer. `off` means the factor is off. `was_off` means it was off already. `no_user` means no account has the address.
7. Tell the person to sign in and turn a method on again. The first method answers new backup codes.

:::caution
Warning: the disable lets the next sign-in pass with the first factor alone. Do it only after the check of step 3.
:::

The test below turns the factor off and signs in with the password alone.

## How it behaves

- The disable deletes the TOTP secret, the factor row, the backup codes, the trusted devices, and the live challenges, in one transaction.
- The disable keeps the sessions of the user. A person who lost the factor has no session to end.
- Core has no delayed self-recovery. A recovery always passes through an operator.
- A later release adds operator tools for this step.
- Migration `0008_schema_v8` deletes each TOTP setup that no enable confirmed. A person who began a setup before the deploy gets `totp_not_enabled` at the enable after it. That person sets up again. This case is not a lost factor.

## If it fails

- [`totp_not_enabled`](/docs/reference/errors/#totp_not_enabled): the user has no factor on. The function answers `was_off`. Tell the person to sign in.

## Update 2026-10-21 by plan 12f

Update 2026-10-21 by plan 12f: the operator tools do step 5 with a record. The text above stays as it was published.

1. Run `authtempo users second-factor-off <base url> <user id> --reason "<reason>" --yes` for step 5.
2. Add `--proof-method <method>`: `document`, `in_person`, `video`, `knowledge`, or `other`.
3. Add `--proof-reference <case id>`: the record of step 4 in your own system, never the evidence.
4. Add `--proof-checked-at <time>`: the time of the check of step 3, at most 7 days old.

- The secret needs the scope `users`. [Run the operator tools](/docs/guides/operator-tools/#the-second-factor) gives the rules of section 26 of the design.
- The method `knowledge` alone is below the level of an enrollment. Use `document`, `in_person`, or `video`.
- Core checks no proof. The audit row `second_factor_disable` keeps the three values, and `hooks.operator.beforeAction` can check them.
- Before step 5, look for a recent change of the address. A person who took the account can change the address, and then ask for a recovery.
- The command turns every method of the user off, and keeps the sessions. The user gets the notice `factor_disabled` unless `account.notices` is false.
- The deployment refuses a check time after its own clock with `invalid_body`.
- A user with the factor off stops the command with [`totp_not_enabled`](/docs/reference/errors/#totp_not_enabled). Tell the person to sign in.
- A secret with no scope `users` gets [`operator_required`](/docs/reference/errors/#operator_required).
- A bad reason, method, reference, or time gets [`invalid_body`](/docs/reference/errors/#invalid_body). A user id that names no user gets [`not_found`](/docs/reference/errors/#not_found).
- A wrong secret gets [`unauthorized`](/docs/reference/errors/#unauthorized). The 600 calls of an hour give [`rate_limited`](/docs/reference/errors/#rate_limited).
- Another change of the user at the same time gets [`conflict`](/docs/reference/errors/#conflict). Run the command again.
- A before hook of your app gets [`hook_refused`](/docs/reference/errors/#hook_refused) or [`hook_failed`](/docs/reference/errors/#hook_failed).
- [`authtempo users second-factor-off`](/docs/reference/cli/users-second-factor-off/) lists each flag and each error.
