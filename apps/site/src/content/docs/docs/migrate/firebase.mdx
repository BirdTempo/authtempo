**For:** an operator and a developer who move an app from Firebase Auth to authtempo.

**What it does:** you export the users of Firebase, import them into core's tables, and change the app's Firebase calls to `@authtempo/client`.

## Before you start

- An API with authtempo and `password` set. Do a [getting started tutorial](/docs/start/) first.
- The Firebase CLI, signed in to the project.
- The password hash parameters of the project, from the console: Authentication, Users, "Password hash parameters". [The command](/docs/reference/import-cli/#the-command) takes `rounds` and `mem_cost` as options.
- `@authtempo/cli` and `@authtempo/legacy-hashes` in the app's workspace. [authtempo import](/docs/reference/cli/import/) is a command of the first.

## Steps

### Export

1. Export the users with `firebase auth:export users.json --format=json`.
2. Read `rounds`, `mem_cost`, the signer key, and the salt separator in the console.

### Carry the passwords

1. Store the signer key and the salt separator as secrets of the API, not in the code.
2. Chain the legacy seam before core's PBKDF2. Pass `["firescrypt"]` as `formats`, and the signer key and the salt separator as `firebase`.

### Dry run

1. Run the import as a dry run, with `rounds` and `mem_cost` of the project.
2. Check the `hashes:` line against `--formats`. It counts the hash formats of the export, such as `hashes: firescrypt 812, none 31`.

The `@authtempo` packages are on npm. Add the CLI to your app with `pnpm add -D @authtempo/cli`, and run each command as `pnpm exec authtempo …`.

```sh
authtempo import firebase --users users.json --firebase-rounds 8 --firebase-mem-cost 14 --formats firescrypt --target postgres --url-env DATABASE_URL --dry-run
```

### Move

Run the real import on a copy of the database only. The one real import into the real database runs at step 9 of [The cutover](/docs/migrate/cutover/), after the old sign-ins stop. If it runs earlier, a password, an address, or a delete that changes in the old system after it is lost. [One real import](/docs/migrate/cutover/#one-real-import) tells why.

1. Make the copy. On Postgres, create an empty database, set `COPY_URL` to its URL, and load the real one into it with `pg_dump --no-owner "$DATABASE_URL" | psql "$COPY_URL"`.
2. On D1, load the real database into the empty local copy of the import Worker with `wrangler d1 export <database> --remote --output copy.sql` and `wrangler d1 execute <database> --local --file copy.sql`.
3. Run both in the folder of the import Worker. Delete its `.wrangler/state` first, or the load stops on a table that exists.
4. Run the same command without `--dry-run`, with `--url-env COPY_URL`. On D1, run the import Worker without `"remote": true`, so it writes the local copy.

```sh
authtempo import firebase --users users.json --firebase-rounds 8 --firebase-mem-cost 14 --formats firescrypt --target postgres --url-env COPY_URL
```

### Verify

1. Run `authtempo import verify` with the same files on the copy. It exits 0 only when the copy holds the whole export.
2. Run `authtempo check <base url>` against the API.
3. Sign in once with a known user and the old password, and once by each other method of the app. Do it at step 13 of [The cutover](/docs/migrate/cutover/): before that step, the real database holds no user.
4. Drop the copy, and on D1 delete `copy.sql`, when `import verify` exits 0. The copy holds every user of the export.

```sh
authtempo import verify firebase --users users.json --firebase-rounds 8 --firebase-mem-cost 14 --formats firescrypt --target postgres --url-env COPY_URL
authtempo check https://api.example.com
```

### Change the calls

## The calls

| Firebase | authtempo |
| --- | --- |
| `signInWithEmailAndPassword(auth, email, password)` | `client.password.signIn({ email, password })` |
| `createUserWithEmailAndPassword(auth, email, password)` | `client.password.signUp({ email, password })` |
| `sendSignInLinkToEmail(auth, email, settings)` | `client.magicLink.request({ email })` |
| `signInWithPopup(auth, new GoogleAuthProvider())` | Send the browser to `/auth/social/google/start?next=/` on the API. There is no popup. |
| `sendPasswordResetEmail(auth, email)` | `client.password.requestReset({ email })` |
| `signOut(auth)` | `client.signOut()` |
| `onAuthStateChanged(auth, callback)` | No event. Call `client.session()` after each sign-in and each sign-out. |
| `user.getIdToken()` | `client.jwt.token()` |
| `verifyIdToken(token)` of the Admin SDK | `auth.session(request)`, or a check of the session JWT against `/auth/jwks` |

## How it behaves

- `rounds` and `mem_cost` are each 1 to 99. The product of 2 to the power of `mem_cost` and `rounds` is at most 2 to the power of 18.
- Other values stop the run before any read.
- The export carries no hash parameters. A wrong value refuses every first sign-in with no line in the report.
- A `github.com` provider imports as GitHub. A custom `oidc.<name>` provider is dropped and listed.
- A user with a `disabled` value other than `false` is skipped.
- Firebase passkeys do not move.

:::caution
Warning: a wrong signer key, salt separator, `rounds`, or `mem_cost` makes every imported password fail. Sign in once with a known user before the cutover.
:::

## If it fails

- The command stops at start: `rounds` or `mem_cost` is out of bounds.
- [`invalid_credentials`](/docs/reference/errors/#invalid_credentials) for every imported user: a hash parameter of the project is wrong.
- The API stops at construction: `firescrypt` is in `formats` without the `firebase` option.
