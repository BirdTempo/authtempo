**For:** an app developer who wants core's pages in the look of the app.

**What it does:** a page function of the config answers the markup. Core sets the headers and serves the page.

## Before you start

- A working setup from a [getting started tutorial](/docs/start/).
- The default page of the same kind, to copy its form fields. Core exports each default.

## Steps

1. Pick the page in the table below, and read its default.
2. Write a function that takes the page input and answers the markup.
3. Escape every value of the input in the markup.
4. Keep the form of the default: the same `method`, `action`, and field names.
5. Set the config key of the table to your function.

## The pages

| Config key | Default | The page |
| --- | --- | --- |
| `magicLink.confirmPage` | `defaultConfirmPage` | The page of a magic link, with one button that posts the token. |
| `handoff.signInPage` | `defaultSignInPage` | The sign-in page of the handoff and of the OAuth authorize step. |
| `handoff.confirmPage` | `defaultHandoffConfirmPage` | The page that names the account and the app before the code is minted. |
| `password.resetPage` | `defaultResetPage` | The form of a reset link. |
| `totp.challengePage` | `defaultTotpPage` | The form of a second factor challenge. |
| `oauth.consentPage` | `defaultConsentPage` | The consent page of the OAuth provider. |

## How it behaves

- Core sets `cache-control: no-store`, `referrer-policy: strict-origin`, `x-robots-tag: noindex`, and a content security policy.
- The policy permits inline style, no script, and a form post to this origin only. A page that needs script needs its own route in the app.
- The sign-in page is the one page with a script: the passkey ceremony, under a nonce. A custom sign-in page must put the nonce on its script tag.
- A custom sign-in page must show `methods.providers`, or the buttons of GitHub, LinkedIn, and the list providers do not show.
- The verify page of a password sign-up has no config key. Core serves `defaultPasswordVerifyPage`.

## If it fails

- A page with a script shows no error, and the browser does not run the script. Move the script to a route of the app.
- A form with other field names posts nothing that core reads, and the flow answers [`invalid_token`](/docs/reference/errors/#invalid_token).
