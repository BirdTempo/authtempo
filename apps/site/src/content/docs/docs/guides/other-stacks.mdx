**For:** a developer on a stack that this site gives no page of its own.

**What it does:** this page names the part of authtempo that fits each kind of stack. Core speaks the web request and response, so most stacks need one line.

## Before you start

- A working setup from a [getting started tutorial](/docs/start/).

## Steps

1. **A runtime that speaks the web request:** Bun, Deno, Cloudflare Workers, or a framework that gives you a `Request`. Call `auth.handle(request)` for each path under `/auth`, as the sample below does.
2. **A Node server on `http`:** use `@authtempo/express` or `@authtempo/fastify`. Their `toWebRequest` and `sendWebResponse` show the conversion for another Node framework.
3. **A front end with no package:** Angular, Qwik, Lit, or plain JavaScript. Use [the client package](/docs/reference/client/), and subscribe to `client.store` for the session.
4. **A server that must know the caller:** use [the verify package](/docs/reference/verify/) in any runtime.
5. **A native or desktop app:** use [the handoff package](/docs/reference/handoff/).
6. **A protected page:** call `readGate` of `@authtempo/core/bindings` with the path that your router matched.

## How it behaves

- `auth.handle` answers every route of core, with its cookies and its CORS headers. Return its answer unchanged, so each Set-Cookie line reaches the browser.
- The sample matches the raw path of `request.url`, the path that core's router reads. It does not decode, keeps the case, and cuts no trailing slash.
- So `/%6De`, `/ME`, and `/me/` reach no page, and `/%61uth/session` reaches no route of core. Each gets a 404.
- A router that decodes the path, folds the case, or cuts a trailing slash runs a page for more than one text. Test the rule on each of those forms.
- A path that your router decodes to a path of core must never run a page.
- An exact rule covers one route only. For a route with a parameter, use a prefix rule.
- Take the origin of a redirect from the Host header. When the Host does not parse, use `new URL(auth.baseURL).origin`.
- Never take the origin from a request line in absolute form. Bun 1.4 builds `request.url` from the Host header.
- A page that reads the session sends the renewed cookie that `auth.sessionCookie` answers.

## If it fails

- [`origin_not_trusted`](/docs/reference/errors/#origin_not_trusted): the page's origin is not `baseURL` and not in `trustedOrigins`.
- [`unauthorized`](/docs/reference/errors/#unauthorized): the request has no session.
