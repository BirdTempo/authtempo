**For:** a developer of a browser extension that calls an authtempo API.

**What it does:** the extension signs a person in by email code and keeps a bearer token. The API trusts the extension's origin.

**Chrome only.** A Firefox extension cannot sign in today: each browser instance has a random origin, and the API answers 403 `origin_not_trusted`.

## Before you start

- A working setup from a [getting started tutorial](/docs/start/).
- The ID of the extension. Chrome shows it on its extensions page. The [`key` field of `manifest.json`](https://developer.chrome.com/docs/extensions/reference/manifest/key) keeps one ID for an unpacked build.
- The [email code](/docs/guides/email-code/) sign-in on the API.

## Steps

1. Add `chrome-extension://` and the ID to `trustedOrigins` on the API. Write the exact origin: core refuses a wildcard.
2. Add the API's origin to `host_permissions` in `manifest.json`.
3. Make the client with `credentials: "omit"` and the stored token as the bearer.
4. Sign in by email code in the popup, and keep the token in `chrome.storage.local`.
5. Clear the token when the session ends. The client calls `onSessionEnd` with the token that ended. Clear the token store only when it still holds that token.
6. Sign out with the `signOut` of the sample. It clears the token store when the server ended the session.

## How it behaves

- Token mode sends no cookie, so no cross-site cookie rule applies. It is the mode of this page.
- Cookie mode needs `cookie: { sameSite: "None" }` on the API, because the extension is another site. This page shows the client of token mode only.
- Firefox gives each browser instance its own [`moz-extension://` origin](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/web_accessible_resources). `trustedOrigins` cannot name it. If Firefox sends that origin, the API answers 403.

## Security

- `chrome.storage.local` is not encrypted on disk, and a content script of the extension can read it. The token is a bearer credential for the whole session.
- Read the token only in the service worker or the popup. Never read it in a content script.
- `chrome.storage.session` keeps the token in memory only. The cost: the person signs in again after each browser restart.
- `host_permissions` lets the extension send any request to the API origin. Name the API origin only.
- Cookie mode sets `SameSite=None` on the API's session cookie for every site, not only for the extension. A request from another site then carries the cookie.
- Token mode is the safer default. Its cookie keeps `SameSite=Lax`, and the client sends no cookie.

## If it fails

- [`origin_not_trusted`](/docs/reference/errors/#origin_not_trusted): the extension's origin is not in `trustedOrigins`, or the ID changed.
- [`invalid_code`](/docs/reference/errors/#invalid_code): the email code is wrong or expired.
- [`rate_limited`](/docs/reference/errors/#rate_limited): too many codes for one address.
