Add the error codes `body_too_large` (413) and `body_busy` (503). Core reads at most the cap of each route of a request body, and refuses a longer body before any parse. The cap is 64 KiB, 256 KiB for the Apple callback, and 8 MiB for the two SSO connection writes. A JSON body nested deeper than 16 or with more than 4096 items answers `invalid_body` before the parse. A form body of more than 128 pairs gets the refusal of a bad form before the parse, at the SAML ACS too. A SCIM body nested deeper than 16 or with more than 65536 items answers 400 `invalidSyntax` before the parse. The body reads of the routes with a cap above 64 KiB hold at most 16 MiB at once in one isolate. A read past it answers `body_busy` (503) with `Retry-After`. The compatibility package reads each request body with core's capped reader, at the cap of the core route of the path. Past that cap it answers `PAYLOAD_TOO_LARGE` (413) at its first read. Past the budget of the large reads it answers `SERVICE_UNAVAILABLE` (503). Before its read of an SSO connection write, it runs core's limit of the SSO manager writes of the user. Core counts that write once. Add the error code `body_timeout` (408). A body read above the floor stops when it gets no bytes for 10 s. It also stops when it runs past the time of its cap at 128 KiB per second, at least 10 s. Both answer `body_timeout`. One client holds at most 4 MiB of the budget of the large reads, or the cap of its read when that is more. The compatibility package answers `REQUEST_TIMEOUT` (408). The budget has two halves of 8 MiB that do not lend bytes to each other. The large reads of signed-in users use one half, and every other large read uses the other. One IP holds at most 4 MiB of its half, and a user may hold the cap of its read. A request with no client IP takes no share of its own, and counts in the anonymous half only. A signed-in user runs one large body read at a time, and a second answers `body_busy` (503) before any byte. The large read of a signed-in user must arrive at 256 KiB per second or more, so an SSO connection write gets 32 s. Core allows 6 large reads of one user per hour, on the new limit `sso-large-read:user`, and answers `rate_limited` (429) past it. The compatibility package counts that limit before its own read of an SSO connection write, and core counts the write once. A request with no client IP now takes the 4 MiB share of one IP. One caller with no header cannot fill the anonymous half. `ipKey` gives a text that is not an IP the key `text:` and the text. So no header text takes the key `unknown` of a request with no IP. A SCIM body read that stalls answers 408 in the SCIM error form, not core's JSON form. The Apple callback form post counts on the new limit `social-callback:ip` before its read, and answers `rate_limited` past it. The compatibility package reads each SSO connection write once. It clones a POST body only on the four password paths that read the copy. An SSO connection write whose large read cannot start answers `body_busy` (503) before the limits of its user, and counts on neither. A read cannot start while its user runs one, or while the user half has no room for its declared length. So a client that sends it again after `Retry-After` keeps its writes of the hour. The compatibility package checks the same before its own count. A write with no declared length that starts counts at its start, and can then get `body_busy` at its first chunk. The request event of a SCIM 503 now carries the code `body_busy`. The request events of a SCIM 408 and a SCIM 413 carry `body_timeout` and `body_too_large`. An SSO connection write whose large read takes more than 8 s spends the rest of its user's window of `sso-large-read:user`. It spends at each end of the read: whole, 408, 413 past the cap, a 503 during the read, or a closed socket. The spend lands in the window in which the read ends. Until that window ends, each SSO connection write of the user answers `rate_limited` (429) before any byte. A write that ends within 8 s spends nothing. The compatibility package spends the same at its own read.
